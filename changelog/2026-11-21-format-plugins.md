# File formats of the specialization via isolated plugin — 2026-11-21 (épico `epic/format-plugins`, PR #2426, MCP 0.54.0, schema v22, specialization formatVersion 20)

## Adicionado

- Specialization `formatVersion` 20: the root key `fileFormats` declares the file formats the specialization reads and writes (`id`, `name`, `extension`, `plugin`, `contract`, `scope`, `description`, `examples`). Each format is handled by a `.js` plugin of the package; a format is cited as `<specId>/<formatId>`. The key is outside the version contract (no `version` raise, no migration) and the earlier versions behave as before. Nothing runs a plugin yet (#1923).
- Package: the `.js` plugin is a text file of the package, read by the app and by `validate_library`/`apply_specialization` and copied to `specs/<id>/plugins/`; level 1 of the library validator checks that the plugin, the examples and the `input` files exist and that the plugin has at most 1 MiB. The `validate_library` summary gains `fileFormats` when the specialization declares formats.
- Plugin contract 1 in the model (`src/model/formatPlugin.ts`, `formatInput.ts`, `formatResult.ts`): the projection a format plugin receives (`buildFormatInput`: the typed annotations of the format's own specialization, the markings and arrows that hold them and their containers, references as in the MCP, scope `project` or `container`), the result it may return (`checkFormatResult`: only `add_container`, `create_marking`, `update_marking`, `create_annotation`, `update_annotation` and `create_arrow`, local `$` aliases, references that exist in the input, errors with the path inside the result) and the limits of a call. Pure and tested; nothing runs a plugin yet (#1923).
- QuickJS executor of the format plugins in the MCP (`mcp/pluginRunner.ts`): `runPlugin` runs a specialization's `generate` or `parse` isolated in QuickJS (WebAssembly embedded in `dist-mcp/mapping-mcp.js`, +776 kB), in a new runtime per call, with no disk, network, storage or host function, a 5 s time limit, a 64 MiB memory limit, a stack limit and the size limits of the contract. Every failure is a typed error (`plugin-failed`, `plugin-timeout`, `plugin-limit`, `plugin-output-invalid`) and none brings the server down. `node mapping-mcp.js --check-plugin-runner` checks the embedded executor. No tool calls it yet (#1923).
- MCP: `export_format` (read-only: the text a format's plugin generates for the project or one container, with the `fileName`; the server never writes the file), the `import_format` batch operation (`text` or `file`, `container`: `parse` runs on the project as the batch sees it at that step, the checked operations are applied inside the step with local aliases, the response lists what was created and updated and the plugin's warnings, and the proposal stores the op with the inline `text` omitted), `get_project.fileFormats` and the error `format-not-found`. `validate_library` loads each plugin (level 2) and runs the examples of each format in both directions on an empty in-memory project (level 3), with the problem at `fileFormats[i]` or `fileFormats[i].examples[j]` (#1923).
- `docs/PLUGIN-FORMAT.md` and the MCP resource `mapping-docs://PLUGIN-FORMAT.md`: the contract (script shape, `generate` and `parse`, the projection with a TypeScript declaration, the allowed operations, the limits and the errors).
- Example package `examples/libraries/data-model/` (no components): the `class` and `endpoint` types of the data model and two file formats, `openapi` (OpenAPI 3.0.3 YAML) and `attributes-csv` (one line per attribute), each a classic-script plugin with `generate` and `parse` and the YAML or CSV reader and writer written inside it, plus an example per format that round-trips. Importing a file creates the classes and endpoints in a container named after `info.title` (CSV: "Data model") and re-reading updates what matches, never deleting (#1923).
- Example package `examples/libraries/sdui-backend/` in `formatVersion` 20 (the `version` stays 3): the `sdui` file format (scope `container`) with a plugin that reads an SDUI screen JSON into a container (screen size and background, the components as markings, the children of a Column in its slot, a bottom bar at the bottom and the FAB at its corner; a `modal` is left out with a warning) and writes the container back as the same JSON, plus the round-trip example `examples/home.sdui.json`. `origins` stays unchanged next to it (#1923).
- Script `R32 — File formats` of the test guide (block 2 of the full round): the two example packages, `validate_library` of valid and broken plugins, `import_format` and `export_format` with proposals accepted in the app, the two errors and the SDUI screen round trip; R10.11 gains `fileFormats: 1` (#1923).
- `spec-author` skill: the step "File formats (`formatVersion` 20)", `docs/PLUGIN-FORMAT.md` in the required reading, the plugin run in "Validate before delivering" and the plugin pitfalls (#1923).

## Alterado

- `import_format` of a format with scope `container` no longer requires `container`: without it `parse` receives `target: null` and creates the container it reads (the SDUI screen); `export_format` still requires it (#1923).
- `validate_library` runs the examples of a format with the components and icons of the package loaded, so a `parse` result that puts a child in a slot is applied as in a project (#1923).
- File formats of the specialization are handled by an isolated plugin running in QuickJS (formatVersion 20) (#1923).
- `docs/SPEC-FORMAT.md`, Help › Specializations, `spec-author` skill and `docs/AGENT-GUIDE.md`: the current format version is 20 and the code coming from a specialization only runs isolated.
- The `dist/index.html` ceiling went up 16 KiB, from 2,359,296 to 2,375,680 bytes, by the budget rule (the formatVersion 20 help text in both languages and the `fileFormats` validation); above the limits, `bug` #2437 for the owner to review.

## Corrigido

- `import_format` in a project with several pages failed with `page-required` whenever the plugin created a container, because the plugin cannot name a page. The operation takes an optional `page` (id or name) that the containers the plugin creates without a page go to. The Help › Specializations text no longer says that nothing runs a plugin: the MCP server does (`export_format`, `import_format`, `validate_library`).
