# Interactive guide and example project

The app ships an **interactive guide** (a separate page, `guia/`) and an **example project** (the repository's `examples/exemplo-completo.zip`, which the person downloads and opens through **Open zip**; the app does not embed it). Both come from the same project, `examples/exemplo-completo/`, the single source: the guide never differs from the example.

## What each piece is

| Piece                        | Where                           | How it gets into the app                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Example project (the source) | `examples/exemplo-completo/`    | `mapping.json` (schema v18, with the "For everyone" perspectives Dados and Material 3 and the arrival of the note "Cadastro"), `images/`, `proposals/` with one open proposal and `comments/` with three conversations (one waits for a human, one waits for an agent, one resolved). The `specs/` (SDUI, Modelo de dados, Notas and the `material3-compose` library) **is not versioned**: it comes from the sources through the `EXAMPLE_SPECS` manifest and is materialized by `build:example`. |
| Example zip                  | `examples/exemplo-completo.zip` | Generated from the folder (outside `specs/`) plus the manifest (`npm run build:example`). It is not embedded in the app: the person downloads it from the repository and opens it through **Open zip** (the same `importZip`); **Help** and the guide say where to download it.                                                                                                                                                                                                                    |
| Guide                        | `public/guia/index.html`        | Generated from the template `scripts/guia/template.html` and the example's `mapping.json` (`npm run build:guia`). Vite copies it to `dist/guia/`, next to the single `dist/index.html`.                                                                                                                                                                                                                                                                                                            |
| Entry points                 | Home screen, **Help**           | **Interactive guide (in Portuguese)** link on the side of the home screen and the first section of **Help** (both open another tab, `rel="noopener noreferrer"`).                                                                                                                                                                                                                                                                                                                                  |

## How the guide is generated

`scripts/buildGuia.mjs` bundles `scripts/guia.ts` with esbuild and runs `guiaHtml()`, which:

1. reads `examples/exemplo-completo/mapping.json` with the app's `deserialize` (the file must be a valid project of the current schema) and the images from `images/` (they become data URIs);
2. replaces in the template the marker `/*__TOKENS_CSS__*/` with the **app's tokens** (`renderTokensCss()`: the light and the dark theme, the same `--color-*`, `--space-*`, `--t-*` names) and the marker `/*__DATA__*/ null` with the subset of the project that the page draws;
3. applies the `index.html` **CSP** (`applyCsp`, `pwa/csp.ts`): no `style=""`, no inline handler, no outside font or script, no network. The layer color goes in through the CSSOM (`el.style.setProperty`), never through an attribute.

The **perspective selector** (the "Perspective" list, above the tabs) and step 14 "Perspectives" come from `mapping.json`: `guiaData` carries each "For everyone" perspective (name, containers by id and hidden layers) and the arrivals (marking name and `fromName`). Choosing one filters the container tabs and turns off the chips of the hidden layers; Main shows everything. Each step of the walkthrough has a perspective (steps 1 to 13, Main; 14, Dados). The per-perspective position and the loose note are not drawn.

The drawing of the Material 3 components in the containers without a photo (the `material3-compose` types: `top-app-bar`, `chip`, `card`, `button`…) uses the **annotation's own values** (title, labels, style, selected…): if the example changes, the guide changes with it. The walkthrough's terms follow the interface (Tree, Layers, Details, Incomplete, Diagnostics, Proposals, Catalog, "locked", "Position needs review"); the shortcuts mentioned come from `SHORTCUT_LABELS` and `WINDOW_NUMBER`, and `tests/examples/guia.test.ts` fails if any of them stops existing in the app.

The guide follows the **app's theme**: it reads `mapping.theme` from `localStorage` (same origin; `light` or `dark`, otherwise the system theme).

## How to regenerate

```bash
npm run build:example   # examples/exemplo-completo.zip and the folder examples/exemplo-completo/specs/ (materialized from the sources)
npm run build:proposal-components # examples/proposta-componentes.zip (see below)
npm run build:suggestions-kotlin # examples/sugestoes-kotlin.zip (see below)
npm run build:guia      # public/guia/index.html, from the template and the example
```

- `npm run build` already runs `build:guia` before Vite. The zip is **not** regenerated in the build: it is checked by a test (`tests/examples/exampleProject.test.ts`).
- The repository keeps both generated files (like `libraries/material3-compose/`). If the example folder or the template changes without regenerating, the `tests/examples/*.test.ts` tests point to the command to run.
- To change the example: edit the folder (preferably opening it in the app with **Open folder** and letting the app write, so that `mapping.json` comes out canonical), run both commands and, if the counts change (4 images, 32 markings, 42 annotations, 10 layers, 4 specializations, 2 perspectives and 1 arrival), adjust `tests/examples/*.test.ts`, the guide's steps (`const S` in the template, which cites screens and markings by name) and R11 of `docs/TESTING.md`.
- **When a library or a specialization changes** (`libraries/material3-compose/`, `libraries/notas/`, or an edit to `examples/specs/sdui.json` / `modelo-de-dados.json`): there is no manual copy. The `EXAMPLE_SPECS` manifest (`scripts/exampleProject.mjs`) lists each destination in `specs/` and the source (`material3-compose/` ← `libraries/material3-compose/`; `notas/` ← `libraries/notas/`, without `index.ts`; `sdui.json` and `modelo-dados.json` ← `examples/specs/`), and `exampleFiles()` returns the example's view: the folder **outside `specs/`** plus the manifest, ignoring the `specs/` on disk. The zip, the zip's test and the materialization use this view. Run `npm run build:example` (and `npm run build:guia`); `build:example` also deletes and rewrites `examples/exemplo-completo/specs/` (ignored by git), for **Open folder** on the example. If only the `version` changes, adjust it in `specializations[]` of `mapping.json`. The zip's test fails with this instruction if the source changes without regenerating; the tests do not depend on the materialized folder, so they pass on a fresh clone without generating anything.
- **Other example zips (not part of the guide).** `examples/proposta-exemplo.zip` (script R4) comes from the generator `tests/e2e/proposalFixture.ts` (`UPDATE_EXAMPLES=1 npx vitest run tests/examples/proposalExample.test.ts`). `examples/proposta-componentes.zip` (script R13: the Telas project with an open proposal of new components, in the pending, accepted, rejected, invalid, changed, unlabeled and proposal-package cases) comes from `tests/e2e/proposedComponentsFixture.ts` through `npm run build:proposal-components`; the test `tests/examples/proposalComponents.test.ts` fails if the zip is out of date and checks the review states when opening it. `examples/sugestoes-kotlin.zip` (script R14: the Kotlin library applied and the data classes `Usuario` and `Endereco`, with an empty Type for the script to fill in) comes from `tests/e2e/suggestionsKotlinFixture.ts` through `npm run build:suggestions-kotlin`; the test `tests/examples/suggestionsKotlin.test.ts` fails if the zip is out of date.
- The example carries no real data: names, emails (`exemplo.com`) and repositories (`github.com/org/…`) are made up.

## Service worker and publishing

- `pwa/sw.js` puts `./guia/index.html` in the precache and serves navigation to `guia/` (and `guia/index.html`) from the cache: the guide works offline. The `sw.js` stamp (`vite.config.ts`) carries the guide's content, so changing only the guide also triggers the new-version notice.
- `deploy.yml` copies all of `dist/`: the main version lives at `/guia/` and the preview at `/preview/guia/`, with no workflow change.
- Opened as a file (`file://`), the `index.html` is usually alone (it is the deploy's standalone artifact): the app does not show the guide link (`src/utils/guideLink.ts`).
- The example zip (289 KB, with the `material3-compose` library and Roboto) is **not** included in `dist/index.html`: embedding it would take the file to 1,868,223 bytes (above the budget of the time, 1.5 MiB), so the **Open example project** button was removed and the app tells the person to download the zip from the repository.

## What opening the example writes

Opening the example is **Open zip** with the downloaded file (the same `importZip`): a new copy of the project in IndexedDB (**On this device**), which starts to appear in **Recent projects**, and the browser's persistent-storage request. It writes nothing to a folder or to **recent folders**. Each opening creates **another copy** (name **exemplo-completo**); **Delete**, in the list, deletes the copy. Test: `tests/app/controller.test.ts` ("the example project (repository zip) opens through importZip").

- `tests/e2e/guia.spec.ts`: the page loads with no console error or CSP violation, **Next** walks through the 14 steps, step 14 opens on the Dados perspective and the selector switches the tabs and chips, the links on the home screen and in Help, the example opens with the proposal to review.
