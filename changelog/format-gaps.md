# Format gaps — [Não lançado] (épico `epic/format-gaps`, PR #2340, MCP 0.49.0, schema v22)

Icons file formatVersion 3; component format 4, specialization and schema unchanged.

## Adicionado

- The `fillRule` of an icon path (icons file `formatVersion` 3): each item of `paths` accepts `"fillRule": "evenodd"` (or `"nonzero"`, the default). With `evenodd` the inner shapes of a path are holes, so an icon exported from Figma or Android no longer needs its subpaths rewritten. It draws the same in the app, in the `render_marking` and `render_container` PNG of the MCP and in the viewer (`mapping-viewer` 0.6.0). `fillRule` in a version 1 or 2 file is `only allowed with formatVersion 3`, at `icons.<name>.paths[i].fillRule`; a value other than `nonzero` or `evenodd` is `expected one of: nonzero, evenodd`.
- The example package `examples/libraries/drawing-keys/`, with the Icon holes component and an icons file in version 3 (`ring`, `square-hole`, `star-evenodd`, plus the icons of `tests/fixtures/svg-icons/` imported through `import_icons`).
- MCP `import_icons({ path, svg, name?, replace?, colors?, mirror?, dryRun? })`: turns `.svg` files (one file or a folder, inside the roots) into icons of the icons file the package declares, with `fillRule`, automatic color and the basic shapes as path data; `dryRun` previews, an existing name is skipped (`icon-exists`) unless `replace: true`, and a file with a problem goes into `errors` without stopping the others. It writes only that `.json`, atomically and after validating it, and refuses a package inside a project's `specs/` (`library-in-project`) and a specialization without `icons` (`icons-not-declared`). See `docs/MCP.md`, "Importing icons (`import_icons`)".
- Component format 4: `font.letterSpacing` accepts a percentage of the font size as text (`"2%"`), each item of a `padding` list (frame, slot, `repeat`, run) accepts a number expression, and `sizing.width`/`sizing.height` accept a number `$token`; the Tag type of `drawing-keys` shows the three. An earlier MCP refuses them with `expected a number` or `$token is only valid…`.
- Component format 4: `scale` (a number ≥ 0, any node, the root included) scales the drawing uniformly around the center of the box, like `rotation` and drawing only (layout, measurement, `hug` and `fit_marking` do not change), and `filter: { "grayscale": 0..1 }` turns a node and its children gray with the CSS `grayscale()` matrix (fills, gradients, strokes, shadows, text and images in the app; the MCP PNG has no image pixels and draws the placeholder of an image as it is). Both reach the drawing of an embedded `component` node, and draw the same in the app, the viewer and the MCP PNG; an image loaded without CORS stays in color in the app. The Pressed Button and Flag types of `drawing-keys` show them. An earlier MCP refuses them with `unknown key: scale` and `unknown key: filter`.
- Component format 4: an `ellipse` accepts `startAngle` and `sweepAngle` (degrees, literal, expression or number `$token`), an arc like `drawArc` without the center. 0 points right and the angle grows clockwise (parametric, as in Skia); a negative sweep goes counterclockwise, `|sweepAngle| ≥ 360` is the whole ellipse and 0 draws nothing. The engine draws it as a `path` whose stroke follows only the arc (with the ellipse's `cap`, `join` and `dash`) and sits where the whole ellipse's would (`align` and `stroke.offset`); the fill closes on the chord. An arc draws one shadow, with no `spread` and no inner shadow. On `rect` the keys are `unknown key`; in a version lower than 4, `only allowed with formatVersion 4`. The Spinner of `examples/libraries/drawing-keys/` shows it.

## Alterado

- The icons file accepts `formatVersion` 1, 2 and 3 (`formatVersion: must be 1, 2 or 3` for any other). Versions 1 and 2 keep validating and drawing as before. An earlier app or MCP refuses a version 3 file at level 1 (`formatVersion: must be 1 or 2`), so it never draws the holes filled: update the MCP first (0.49.0).
- The `dist/index.html` ceiling went up 16 KiB, from 2326528 to 2342912 bytes, by the budget rule (FG1: 1001 bytes over); above the limits, `bug` #2339 for the owner to review.
