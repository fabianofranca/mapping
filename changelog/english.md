# Whole project in English — [Não lançado] (épico `epic/english`, PR #0, MCP 0.41.0, schema v20)

## Alterado

- **Language rule in `CLAUDE.md` (for whoever runs the flow, #741, ID1):** everything in the repository and on GitHub (code, comments, documentation, tests, messages, commits, issues and PRs) is written in English; Brazilian Portuguese stays only in the app's pt-BR dictionary, the interactive guide's pt-BR strings, the locale tests, the declared fixtures, the protocol terms (`PROTOCOL_TERMS`) and `mappings-workspace/`. Chats with the owner stay in Portuguese. The line that allowed comments and documentation in Portuguese is gone.
- **`CLAUDE.md` and `README.md` translated to English (#741, ID1):** no rule changes meaning; the section titles are now in English (`Project`, `Commands`, `Architecture rules`, `Runtime environment restrictions`, `Code`, `Workflow (summary)`, `Mapping workspace` in `CLAUDE.md`), and the anchors that stage sheets cite follow them (for example `CLAUDE.md#architecture-rules`): a sheet that still cites an old slug (`CLAUDE.md#regras-de-arquitetura`, `README.md#como-testar`) is rejected by `painel.py toca` until it is redone, as the stage plan foresees after the epic merges.
- **i18n with en-US as the base dictionary (#741, ID3):** `Dictionary` is now `Record<keyof typeof enUS, string>` and `pt-BR.ts` is typed against it, so removing a key from the pt-BR dictionary (or from a pt-BR part of `catalog`, `review`, `perspectives` or `modelMessages`) fails the typecheck. The comments that give context to each key live in `en-US.ts`, in English; `pt-BR.ts` holds only the values. `t()`, `detectLocale` and `mapping.locale` behave exactly as before (the default language is unchanged) and no UI string changes in either language.
- **Help → Specializations, en-US examples in English (#741, ID3):** the sample data inside the code blocks of the en-US page (names, descriptions, notes, messages and the package tree comments) was still Portuguese; it is now English, the same as `docs/SPEC-FORMAT.md`. The pt-BR page is unchanged.
- **MCP messages, descriptions and agent guide in English (#741, ID5, MCP 0.41.0):** the descriptions of every tool and parameter, the error and return messages, the embedded `docs/AGENT-GUIDE.md` (also published as `mapping-docs://AGENT-GUIDE.md`) and `docs/MCP.md` are now in English, together with the `spec-author` skill and the `examples/workspace/` files (`AGENTS.md`, `README.md`, `setup.sh`, `watch-comments.mjs`), whose copies in `mappings-workspace/` stay identical. Tool names, parameter names, batch `op`s and error `code`s do not change, so a client that matches codes keeps working; a client that matched message text must match the English text. The sentence the docs use for the current format version is now "The current format version is N".
- **Libraries in English (#741, ID7, part 1):** the text of `libraries/**` (labels, descriptions, `notes`, component node names, example names and values, component documents and the `README.md`) is now English; ids, field keys, option values and folder names are unchanged (decision 7). Library `version`s went up: `kotlin` 2 → 3, `material3-compose` 14 → 15 (the slider migrations now end at 15) and `notas` 3 → 4. The Kotlin options `sim`/`não` and `construtor`/`corpo` stay as stored data. The example zips were regenerated.
- **Examples and interactive guide in English (#741, ID7, part 2):** the example project is now `examples/full-example/` (and `examples/full-example.zip`), with English layer, screen, marking and proposal names, and the example specs, libraries and zips renamed (`data-model.json`, `roles-migration.json`, `page.measured.json`, `libraries/measured`, `proposal-example.zip`, `proposal-components.zip`, `suggestions-kotlin.zip`). The interactive guide is bilingual (en-US and pt-BR) and lives in `guide/` (`npm run build:guide`, `scripts/guide.ts`, `scripts/guide/messages.ts`): it picks the language by `mapping.locale` and then by `navigator.language`; the old `guia/` address is a redirect page to `guide/`. The paths, names and example texts cited in `CLAUDE.md`, `README.md`, `docs/GUIDE.md`, `docs/FORMAT.md`, `docs/TESTING.md` and the `spec-author` skill follow the new names.
