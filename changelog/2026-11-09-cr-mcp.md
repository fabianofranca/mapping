# CR of the MCP — 2026-11-09 (epic `epic/cr-mcp`, PR #1295, MCP 0.28.13, schema v18)

## Corrigido

- `render_marking`, `render_container` and `get_marking_image`: the stroke of a closed path whose last point repeats the first has the join at the starting corner, like the same path without the repeated point.
- An SVG path with arc flags stuck together, without a separator (`a5 5 0 1110 0`), is read as in SVG (each flag is a `0` or `1` digit); before, the path vanished silently.
- `stroke.scale: false` gives the server drawing the same width as the app (in output pixels, at any zoom).
- A drawing with more than 200 thousand points in a single node no longer overflows the stack.
- `get_container_file`: a JPEG image with EXIF orientation no longer comes back with the original bytes (the orientation tag contradicted the already rotated dimensions in the JSON); the image is re-encoded already rotated (`recoded: true`).
- `render_marking` and `render_container` warn (`warning`) when the image file has dimensions different from the project's, like `get_marking_image`, and the background of the fractional region stays aligned with the drawing (before it was misaligned by up to 1 px).

- `update_arrow` in a proposal under review (`revise_proposal`) no longer warns that the change "does not enter the proposal" when the arrow was created by the proposal itself; the warning applies only to an arrow that is already in the project.
- The `as` (or `annotationAs`) of an operation equal to a row `_as` of the same operation gives `duplicate-alias`, instead of silently overwriting the alias.
- `import_measured`: an internal error (that is neither the tool's nor the model's) is raised as an error, instead of turning into a "not created" warning for the node; the tool and model errors still turn into a warning.
- `plan_changes` and `propose_changes` read `mapping.json` only once per call: a write between the two earlier reads no longer gives a spurious `revision-conflict`.

- `create_project` no longer overwrites a `mapping.json` that appeared in the folder between the check and the write: the write is exclusive and the error is the usual `already-exists`.
- With several roots, a project cited by path (`apps/cadastro`) that only exists in the second root is found, even if the folder with the same path exists (without a project) in the first.
- The `mapping-mcp.js` bundle again carries the license notices (Apache-2.0, MIT) of the embedded dependencies, at the end of the file (`legalComments: 'eof'` and the packages' `LICENSE` files); the release's file list does not change.
- The description of `get_project` says `repos` (as the code returns), in place of `repo`.

- `wait_for_comment`: a message from a person written right after the wait starts is returned in the same wait (before it only appeared with another change); a wait canceled by the client ends with the code `cancelled`, not `not-open`.
- `post_message` and the `thread` of `propose_changes`: if the project cannot be reread after the message is written, the answer is a success with the `reply-incomplete` warning (before it was an error, which led the agent to repeat the message, and the proposal said the message was not written).
- A proposal with an unreadable `proposal.json` gives `invalid-proposal` (as the guide says), not `proposal-not-found`.

- `validate_library`, `plan_library_update` and the batch that applies or updates a library warn (`ignored-paths`) which package folders the read skipped (subfolders beyond 8 levels, hidden ones and `node_modules`); before they were left out without a notice.
- `plan_library_update` reads the package like `validate_library` (without reading the binaries and without the app's 500-file limit): a package that `validate_library` accepts is no longer refused by the preview with `package-too-large`.

## Alterado

- `list_threads` with `text` or `anchor` and without `status`/`awaiting` lists the open conversations of any `awaiting`, and no longer only those waiting for the agent (before it omitted conversations without a warning); with no filter at all it is still the inbox.
- Conversations and proposals: less repeated work (`list_threads` and `wait_for_comment` read the project, conversations and proposals in parallel and the list of conversations only once).

- `find_by_code`: each match also brings `path` (the project folder's path relative to the root, as in `list_projects`), to tell apart folders with the same name.
- Less repeated work when reading projects: `loadProject` parses `mapping.json` once; the component catalog and the libraries' fonts stay in the process cache (by path, size and `mtime`: a file replaced on disk invalidates it); `list_projects` does not parse fonts; the `realpath` of the roots and the project discovery are done once per tool call.

- `render_*` and `get_marking_image`: less repeated work (font cache by family, weight and italic; the image read checks the size before reading and does not copy the bytes; the `component-overflow` proof reuses the drawing cache).
- `plan_changes` and the batch: less repeated work (the values of an annotation resolve the type once per call, the types with a component are indexed once and the changes are computed once per `plan_changes`).
- `list_markings`, `get_marking`, `list_components` and the package read: the position among siblings comes from an index built once per call, `get_marking` builds the list of children only once and the package read does not copy the buffers (identical output).
