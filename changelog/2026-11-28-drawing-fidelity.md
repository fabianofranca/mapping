# Drawing fidelity — 2026-11-28 (épico `epic/drawing-fidelity`, PR #3098, MCP 0.73.0, schema v26 unchanged, viewer 0.13.0)

## Adicionado

- Component format 4: an expression (`$switch`, `$if`, `$field`, the math, `$var`) in each item of a `cornerRadius` list, in `image.fit` and in the shadow numbers `x`, `y`, `blur` and `spread` (also in each shadow of a list), so a component no longer repeats a node or a list per value (#2914). A result outside the set draws the default (0, `cover`) and the drawing warns `invalid value in cornerRadius: <value>`, `invalid value in image.fit: <value>` or `invalid value in shadow.<key>: <value>`. In a version lower than 4 each is `only allowed with formatVersion 4`, at its path. The app, the viewer and the MCP PNG draw them the same way.
- Example package `examples/libraries/drawing-fidelity/`: the Corner card (four corner radii from two fields), the Photo (the package image with the `fit` of a field) and the Signal (an outer shadow whose `y` and `blur` follow a size field, with an `evenodd` ring icon on top). Later phases of the stage add types to it.
- Component format 4: `shadow.inner` is valid on `path` and `icon` (on `text` or `image` the error is `shadow.inner: only valid on frame, rect, ellipse, path and icon`). On a `path` the shadow follows the path with its fill rule; on an `icon` it is the union of its paths, each with its fill rule, inside the icon's `clip`, so it lies over each glyph. It sits above the fill and below the stroke; `spread` is ignored. A list on a `path` or `icon` draws the first outer shadow and every inner one. An `ellipse` arc draws its inner shadow too. The app, the viewer and the MCP PNG draw it the same way; the Signal of the example package has it on its icon.
- Component format 4: `stroke.cornerRadius` (`frame` and `rect`): the radius of the outline the stroke is drawn on, which replaces the node's radius plus `offset`. The example package `examples/libraries/drawing-fidelity/` gains the Divider and Link types.
- Component format 4: `overlay: true` draws a node above the child markings of the same container (a scrollbar over a list). A literal boolean, valid on any node but the root; the layout, measurement and anchors do not change, only the drawing order. The MCP PNG draws it (`render_marking`, `render_container`); the app, the Catalog and the viewer draw it too (next entry). No effect in a `screen` component or inside a `component` node. The example package `examples/libraries/drawing-fidelity/` gains the Scroll and Block types.
- Component format 4: the `overlay` nodes are now drawn above the child markings in the app's canvas (a floating marking keeps its overlay in the floating layer, and a drag moves both groups together), in the Catalog and the example images (a lone drawing paints its overlay last) and in the viewer (the instances in order, then the overlays, each with its instance's clip), as the MCP PNG already did. The overlay does not take clicks: a click on the scrollbar over a child selects the child, and a second click goes up to the Scroll, as before.
- Component format 4: `backdropBlur` on `frame` and `rect` (a number >= 0 in component units: literal, expression or number `$token`) blurs what is drawn under the node like CSS `backdrop-filter: blur(<n>px)`, clipped to the node's shape and drawn before its fill so a translucent fill tints the blur; it scales with density and zoom, and with `overlay: true` a bar blurs the child markings under it. The app and the viewer blur the component drawings below it in the same canvas layer (not the container image) and the MCP PNG blurs everything below it, image included. Without `ctx.filter` the node draws without the blur and the drawing warns `backdrop-blur-unsupported`; a value that resolves invalid warns `invalid value in backdropBlur: <value>` and draws 0. In a version lower than 4 it is `only allowed with formatVersion 4`. The example package `examples/libraries/drawing-fidelity/` gains the Header type; the `spec-author` skill and the docs mention it.
- `spec-author` skill, `docs/AGENT-GUIDE.md`, `docs/COMPONENT-FORMAT.md`, `docs/component.schema.json` and `docs/MCP.md`: the new expression positions and the "Update the MCP first" note.
- Test script R55 (Drawing fidelity, 14 steps, in `docs/TESTING.md`, block 3 of the full round) and the parity test `tests/e2e/drawingFidelityParity.spec.ts`: the components of `examples/libraries/drawing-fidelity/` drawn by the app and by the MCP raster with the same probes (the Corner card's corners, the Signal's shadows, the Divider's arc stroke, the Link's ring, the Scroll's scrollbar and the Header's blur). Summary of the stage: expressions in `cornerRadius` items, `image.fit` and shadow numbers; `shadow.inner` on `icon` and `path`; a `sides` stroke that follows the radius; `stroke.cornerRadius`; `overlay`; `backdropBlur`; one example package; MCP minor 0.71.0.
