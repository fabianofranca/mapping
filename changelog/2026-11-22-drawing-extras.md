# Component drawing extras — 2026-11-22 (épico `epic/drawing-extras`, PR #2486, MCP 0.57.0, schema v23 unchanged)

## Adicionado

- A component's `fill` accepts the `radial` gradient (`center`, `radius`, `stops`; always a circle) and the `angular` gradient (`center`, `angle`, `stops`; a sweep that starts at `angle`, clockwise), literally or as the result of `$switch`/`$if`. The app draws them with Konva's radial fill and the canvas `createConicGradient` (without it, the first stop's color and the `angular-gradient-unsupported` warning).
- The MCP raster (`render_marking`, `render_container` and `get_marking_image`) now paints linear, radial and angular gradients per pixel instead of using the first stop's color; a stroke or a text still use the first color. An MCP before 0.57.0 rejects the new types at their path.
- A component's `shadow` accepts `inner: true` (a literal boolean, only on `frame`, `rect` and `ellipse`) for an inner shadow, like CSS `inset`: drawn inside the shape, clipped by its outline, above the fill and below the stroke and the children, alone or mixed with outer shadows in a list (the limit of 4 counts both). The app, the viewer and the MCP PNG draw it, and the root's clip ignores it. On any other node type it is a validation error (`shadow.inner: only valid on frame, rect and ellipse`). The `drawing-extras` example gains the Inner shadow type.
- A component's `image` node `src` can cite an image file of the library package (component format 4): a literal package path (`.png`, `.jpg`, `.jpeg` or `.webp`, relative to the specialization's folder), a `{ "$field" }` whose value is a path, or a `$switch`/`$if` whose every result is a path. Each cited image is up to 1 MB and 2048 px, and the cited images add up to 8 MB. `validate_library` checks existence, format and limits (`file not found`, `image is not PNG, JPEG or WebP`, `image larger than 1 MB`, `image larger than 2048 px`, `the package images exceed 8 MB`) and counts `images` in its summary; the MCP PNG draws them (next item), and the app and the viewer draw them too (next item).
- The MCP PNG (`render_marking`, `render_container` and `get_marking_image` of a container without a file) draws the images of the library package: PNG, JPEG (with its EXIF orientation) and WebP are decoded with the server's codecs from the project's `specs/<id>/` copy, cached by file (path, size and `mtime`), and painted with the `image` node's `fit` and `cornerRadius`, the fill behind it, the opacity and `filter.grayscale`, sampled bilinearly. A missing, corrupt or over-limit image (1 MB and 2048 px each, 8 MB in all) is the placeholder and the response's `warning` names it; a remote image is still the placeholder.
- The app and the embeddable viewer draw the images of the library package, with no network request and no change to the app's CSP: the bytes of the cited files are decoded in the browser (`createImageBitmap`, the EXIF orientation applied) and drawn on the canvas and in the Catalog with the `image` node's `fit`, corner radius and opacity. While an image decodes, or when it cannot be decoded, the drawing shows the placeholder; a package image never asks for consent and is not listed in Diagnostics › Remote images. Applying a folder or a zip whose cited image is over 1 MB or 2048 px, or is not the format its extension names, is refused with the validator's message. The viewer draws the bytes the host passes to `loadLibrary` (`TextFile.bytes`), and `mapping-viewer` is now 0.7.0.
- A component's grid (`layout.type: "grid"`) accepts a list of tracks in `columns` (vertical grid) and `rows` (horizontal grid), literally or as the result of `$if`/`$switch`: 1 to 24 items, each a number of px, a share `"<n>fr"` of what is left (`"2.5fr"` is allowed) or `"hug"` (the largest child with `span` 1 placed in the track). The `fr` tracks split what is left after the px tracks, the `hug` tracks and the gaps, never below 0; a child with `span` greater than 1 occupies the sum of its tracks plus the gaps; a grid that hugs its axis asks for px + `hug` tracks + gaps and, with `fr` tracks, for the largest cell need divided by its `n` times the total of `n`. It works in the frame, in a `repeat` with `layout`, in a slot (Arrange and the first free cell put each child marking in its cell, and a `hug` track measures the children already in it) and in the screen without geometry. An integer still means equal `1fr` tracks, drawn exactly as before; the error for a value outside the set is `layout.columns: expected an integer greater than or equal to 1 or a list of tracks`, per item `expected a number ≥ 0, "<n>fr" or "hug"`, and `expected 1 to 24 tracks`. A list in a `formatVersion` 1 to 3 component is `only allowed with formatVersion 4`. The `drawing-extras` example gains the Uneven grid type.
- A remote image that failed to load (any reason, timeout included) or is too large draws a **failure look**: the placeholder's gray fill, the X and a dashed outline of the box in `#d9480f` (token `cv-component-image-failed`, `palette.failedLine` in the viewer), on the main canvas, in the Catalog and in the viewer; an empty `src`, a pending consent, a refused URL and a loading image keep the neutral placeholder. The Catalog gallery redraws when an image fails and lists a warning naming the origin (`remote-image-failed`); an image loaded without CORS shows there with the failure look and the `remote-image-opaque` warning (it only shows on the main canvas).
- Component format 4, the specialization format and the project schema (v23) do not change: the new types enter `formatVersion` 4 without bumping it, and a `formatVersion` 1 to 3 component that uses them is `only allowed with formatVersion 4`.
- Test script R42 "Component drawing extras" (`docs/TESTING.md`, block 6 of the full round): it validates the package and three broken copies (3000 px image, a `.png` that is a JPEG, a URL in a `$switch`), applies it to a folder project, probes the pixels of the gradients, the inner shadow, the three package images and the uneven grid in the app and in the MCP's PNG, and checks that a package image never asks for consent. It took R42 because R32 (File formats) and R41 (Container classes) were taken.

## Alterado

- The docs (`COMPONENT-FORMAT.md`, the `spec-author` skill, the agent guide, `ARCHITECTURE.md` and the viewer README) state that a remote image's server must send `Access-Control-Allow-Origin` (check with `curl -sI`), and what happens without it: the failure look, "failed to load" in Diagnostics, and the image shows only on the main canvas when Settings › Privacy › "Show images from servers without CORS" is on.
- Ceiling of `dist/index.html` went up 16 KiB, from 2375680 to 2392064 bytes, by the budget rule; above the limits, `bug` #2498 for the owner to review.
- Ceiling of `dist/index.html` went up 32 KiB, from 2408448 to 2441216 bytes, by the budget rule (SM1 sync with `main`); above the limits, `bug` #2534 for the owner to review.
- `COMPONENT-FORMAT.md` "Known limits" lists what the stage leaves out: no image fill outside the `image` node, no SVG or animation in package images, no elliptical radial gradient and no gradient on the stroke; the agent guide says what the PNG draws (gradients, inner shadow, uneven tracks); `examples/README.md` cites the script.
