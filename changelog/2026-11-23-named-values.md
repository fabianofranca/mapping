# Named values v2 in the specialization — 2026-11-23 (épico `epic/named-values`, PR #2748, MCP 0.59.0, schema v24, specialization formatVersion 23)

## Adicionado

- Specialization `formatVersion` 23: `tokens` become a real value system. Aliases (`{ "$token": "<name>" }`, with `alpha`/`over` on a color), composite values (a plain object of named fields, read as `name.field`), mode axes (`tokens.axes` and the `{ "$axis": … }` per-axis value; `modes` stays valid), metadata (the `$value` wrapper with `$description`, `$group` and `$notices`) and the `{ "$tokens": "<group>" }` item in `suggestions`, which expands to the text values of a group when the specialization is parsed. Versions 1 to 22 stay accepted unchanged.
- `examples/libraries/analytics` (version 4, `formatVersion` 23): the event names as tokens in the `events` group, one deprecated name, and the `event.name` and `transition.event` fields suggesting them.
- Components read the named values in two new ways (component `formatVersion` 4 unchanged, specialization `formatVersion` 23): a field by dot, `{ "$token": "title.size" }`, wherever a scalar `$token` applies (including `alpha`, `over`, `let` and `provide`), and the whole composite in `font` and in a shadow, `"font": { "$token": "title", "align": "center" }` (the explicit keys next to `$token` win; in a shadow with `$token`, `color` is no longer required). `validate_library` reports, with the node's path, a whole composite where a scalar goes (`the token "title" is a composite; read one field (title.<field>)`), `the token "x" has no field "y"`, `the token "x" is not a composite` and `field "<f>" of the token "x" is not a key of font` (or `of shadow`), and warns, never errors, when a component reads a deprecated or removed token (`the token "x" is deprecated: <message>`). The drawing proof runs one pass per entry of each axis of `tokens.axes` (messages cite `mode light` or `theme=dark`). The viewer's `drawingMode` option takes a string (that entry on every axis that declares it) or a map from axis to entry.
- Project schema **v24**: the drawing mode is a map axis → entry (`{ "theme": "dark", "contrast": "high" }`), at the root and in `containers[].drawingMode`, so a project with a multi-axis library stores one entry per axis. The effective entry per library axis is the container's, else the project's, else the axis default; a container pins only the axes it lists and follows the project in the others, and the canvas marking follows the project. An axis or entry no applied specialization declares is kept, drawn with the default, and Diagnostics warns. Migration v23 → v24: a string `s` becomes `{ "mode": s }` (backup in `backups/` and the banner as in any migration).
- Proposal `formatVersion` 12: a proposal that carries a drawing mode map (the `project` entity, a container's `drawingMode`) is written in 12; a proposal of 6 to 11 with a string is read as `{ "mode": s }`, and the review shows `theme: dark, contrast: high`.
- MCP 0.59.0: `update_project`, `add_container` and `update_container` take `drawingMode` as a map (replaces the whole map), a string (that entry on every declared axis that has it; `invalid-arguments` with the declared axes when none has it) or `null`; `get_project` returns `drawingMode` (a map or `null`) and `drawingAxes`; `get_container`, the containers of `get_project` and the rows of `list_markings` return `effectiveDrawingMode` as a map with every declared axis; `render_marking` and `render_container` take `drawingMode` as a string or a map; `get_specialization` carries the `tokens` index (per name `kind`, `value` or `fields`, `aliasOf`, `varies`, `description`, `group`, `notices`).
- Container and screen background by token (NV4): the `background` of a container without a file is `#RRGGBB` or `{ "$token": "<name>" }` (schema v24, strict object, name `[a-z0-9][a-z0-9-]*`). It resolves in the container's effective drawing mode, in the first applied specialization that declares the name as a color; alpha is composited over white and `transparent`/`none` become white; an undeclared token draws `#FFFFFF` and Diagnostics lists it. A container with a file keeps `background: null`.
- Specialization `formatVersion` 23: a preset `containers[].background` and an origin's `screen.background` (the whole value, an entry of `values` and `default`) accept `{ "$token": "<name>" }` of a color token of the same specialization (`the token "x" does not exist in the specialization tokens`, `… is a number, but a color is expected here`); `screenFromSource` resolves it in the drawing's selection and the viewer follows its `drawingMode`.
- Proposal `formatVersion` 12 also carries a creation or a `background` change with a token (`a background token only exists in formatVersion 12 or later` below it); the review shows `token <name>`. The background token stays outside the specialization's version contract.
- MCP 0.59.0: `add_container`, `update_container` (and the old `update_image`) take `background` as `"#RRGGBB"` or `{ "$token": "<name>" }`; a token no applied specialization declares as a color is `invalid-arguments` with `details.colorTokens`. `get_project`, `get_container` and `resolve` return `background` as stored and `resolvedBackground`; `render_container`, `render_marking` and `get_marking_image` paint the resolved color (with the pinned axes under `drawingMode`). `add_blank_image` stays `#RRGGBB` only.
- The app never writes a token background; Details shows it read-only with **Use a fixed color**, and the **New container** dialog fills a preset's token with its resolved color.
- App (NV5): Settings shows one list per declared drawing axis (the `mode` axis keeps "Drawing mode", another is labeled by its name) and the container Details one field per axis, with "Follow the project" removing only that axis. The Specializations window lists the axes and, per named value, its default-selection value, `→ target` for an alias, the composite fields, the description, the group and the notice badges.
- Example package `examples/libraries/named-values` (NV6): a small design system with the `theme` and `contrast` axes, a base palette, aliases (one with `alpha`), the composites `title` and `raised`, a deprecated token, the types Card (whole composites in `font` and `shadow`) and Badge (`title.size`), and a `Screen` preset (360 × 640) whose background is `{ "$token": "surface" }`.
- Test script R31 — Named values in `docs/TESTING.md` (block 3 of the full round), and the steps that read a stored or returned drawing mode swept to the map form and to schema v24.

## Corrigido

- A library with `tokens.axes` and no other tokens was drawn and proved as if it had no tokens.
- A component that read a whole composite token where a scalar goes validated with no error; `validate_library` now refuses it.
- With the project open and its folder moved, renamed or deleted, "Check the folder now" no longer empties the proposals list or raises "Proposal deleted outside the app": the list stays as it was and the window says the folder is unavailable and how to locate it again (R12.20).
- A drawing-mode axis stored in the project but no longer declared by any specialization can now be removed from Settings (a "Default" option clears it).
- `get_specialization` returns the specialization as written: `{ "$tokens": … }` suggestions are kept and the internal `suggestionsSource` key no longer leaks.
