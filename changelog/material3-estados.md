# Material 3 with interaction states — [Não lançado] (épico `epic/material3-estados`, PR #1293, MCP 0.28.14, schema v18)

## Adicionado

- `material3-compose` library (version 4): the `button` gains the `interaction` field (Interaction: `none`, `hovered`, `focused`, `pressed`; default `none`) that draws the resting look of the Compose state — the state layer in the content color and the elevation per state. With `enabled` `false` the disabled look wins. The field stays out of the `code`.
- Tokens `state-hover` (0.08), `state-focus` (0.10), `state-pressed` (0.10) and `state-dragged` (0.16), from Compose's `StateTokens.kt`, and `state-disabled-container-filled` (0.1) and `corner-checkbox` (2), which replace the last opacity and radius literals.
- `spec-author` skill, `docs/COMPONENT-FORMAT.md` and `docs/SPEC-FORMAT.md`: the rule "motion outside the drawing, state look as an optional `enum` field".
- `material3-compose` library: Compose's initial sizes in five types — `top-app-bar` 412 × 152 (the height of the large one; the medium and the large fit without overlapping the top row), `date-picker` 360 × 512 (the sixth row of the grid), `time-picker` 328 × 528 (the clock margin and the dialog's action row), `alert-dialog` 312 × 248 (button row of 48) and `slider` 328 × 48 (the 44 track stays centered). Markings already created keep their own rectangle and do not change; the new size applies to the next ones.
- Examples of the known limits: `button` "Long label", `time-picker` "24 hours, fields" and `date-picker` "Range until the end of the month"; each one's Fidelity cites the roadmap that would resolve it (#897, #898). The three-line one of the `snackbar` waits for #898 (today the engine warns that the content goes past the box).
- `material3-compose` library: the `interaction` field reaches eleven more types — `fab`, `extended-fab`, `icon-button`, `icon-toggle-button`, `chip`, `card`, `checkbox`, `radio-button`, `switch`, `slider` and `segmented-button` (`none`, `hovered`, `focused`, `pressed`; `chip` and `card` also `dragged`). They draw the state layer, the elevation per state (FABs, chip, card), the focus outline, the 28 handle of the pressed `switch` and the narrow handle of the `slider`. In the `segmented-button` it applies to the selected segments. One example per state in each type.
- `material3-compose` library: the `interaction` field reaches five more types — `text-field`, `secure-text-field`, `search-bar`, `dropdown-menu` and `list-item`. In the text fields, `hovered` and `focused` draw what the Compose tokens define: focus takes the indicator (filled) or the outline (outlined) of 2 and the label in `primary`, and the mouse in error goes to `on-error-container`. The `search-bar` gains `hovered`, `focused` and `pressed` and the `list-item`, plus `dragged` with the level 4 shadow, as a state layer. In the `dropdown-menu` the state applies to the exposed field and to the selected item of the menu, marked by the new `selected` column of the `items` table (`secondary-container` background; optional, the default is `false`). One example per state in each type.
- `material3-compose` library: the `interaction` field reaches the last five types — `tabs`, `navigation-bar`, `short-navigation-bar`, `navigation-rail` and `navigation-drawer` (`none`, `hovered`, `focused`, `pressed`), closing the 22 types with an interaction state. The state layer applies to the selected item (the tab, the indicator or the item's pill) and takes the Compose ripple color; with no selected item nothing changes. One example per state in each type (the example keeps only simple values and the `items` table does not fit in it: the state shows in the Catalog preview and in the marking with `items`). Their `docs/<type>.md` stops saying that the drawing is static. Script R17 with the state steps (R17.14 and R17.15).

## Alterado

- `slider` (`steps`), `tabs` (`style`) and `snackbar` (`actionOnNewLine`): the field descriptions now say what the drawing does (marks from 1 to 9, indicator of 3 in both styles, 92 with the action below).
- `docs/surface.md`: records the decision to keep the reading of `Surface.kt` on tonal elevation.
- `docs/COMPONENT-FORMAT.md` and `docs/SPEC-FORMAT.md`: the drawing mode follows the `drawingMode` of the project and of the container, and the MCP uses the embedded Mapping Sans (texts that had become outdated).
