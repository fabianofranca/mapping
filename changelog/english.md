# Whole project in English — [Não lançado] (épico `epic/english`, PR #0, MCP 0.41.0, schema v20)

## Alterado

- **Language rule in `CLAUDE.md` (for whoever runs the flow, #741, ID1):** everything in the repository and on GitHub (code, comments, documentation, tests, messages, commits, issues and PRs) is written in English; Brazilian Portuguese stays only in the app's pt-BR dictionary, the interactive guide's pt-BR strings, the locale tests, the declared fixtures, the protocol terms (`PROTOCOL_TERMS`) and `mappings-workspace/`. Chats with the owner stay in Portuguese. The line that allowed comments and documentation in Portuguese is gone.
- **`CLAUDE.md` and `README.md` translated to English (#741, ID1):** no rule changes meaning; the section titles are now in English (`Project`, `Commands`, `Architecture rules`, `Runtime environment restrictions`, `Code`, `Workflow (summary)`, `Mapping workspace` in `CLAUDE.md`), and the anchors that stage sheets cite follow them (for example `CLAUDE.md#architecture-rules`): a sheet that still cites an old slug (`CLAUDE.md#regras-de-arquitetura`, `README.md#como-testar`) is rejected by `painel.py toca` until it is redone, as the stage plan foresees after the epic merges.
- **i18n with en-US as the base dictionary (#741, ID3):** `Dictionary` is now `Record<keyof typeof enUS, string>` and `pt-BR.ts` is typed against it, so removing a key from the pt-BR dictionary (or from a pt-BR part of `catalog`, `review`, `perspectives` or `modelMessages`) fails the typecheck. The comments that give context to each key live in `en-US.ts`, in English; `pt-BR.ts` holds only the values. `t()`, `detectLocale` and `mapping.locale` behave exactly as before (the default language is unchanged) and no UI string changes in either language.
- **Help → Specializations, en-US examples in English (#741, ID3):** the sample data inside the code blocks of the en-US page (names, descriptions, notes, messages and the package tree comments) was still Portuguese; it is now English, the same as `docs/SPEC-FORMAT.md`. The pt-BR page is unchanged.

## Adicionado

- **`tests/tooling/portugueseAllowlist.ts` with the `PROTOCOL_TERMS` list (for whoever runs the flow, #741, ID1):** the frozen machine vocabulary (values written to the panel, outputs read by skills and scheduled prompts, phrases of the notices between sessions, section titles of the records and markers of the issues), each term with the file that produces or reads it. No test uses the list yet; the guard that does is the work of phase ID10.
- **Parity tests for the bilingual i18n modules (#741, ID3):** `tests/i18n/dictionaries.test.ts` checks `catalog`, `review`, `perspectives` and `modelMessages` one by one (same keys and same `{parameters}` in en-US and pt-BR), and `tests/i18n/specHelp.test.ts` checks that the pt-BR and en-US help describe the same format (same terms, ids and code, only the sample prose differs) and that the en-US examples carry no Portuguese.
