# MCP fonts with unsupported GSUB, `fit_marking` and `measure_component` — 2026-11-19 (épico `epic/mcp-fonts-fit-measure`, PR #2255, MCP 0.47.0, schema v20)

## Adicionado

- `measure_component({ project, specId, type, values?, container?, size? })`, a read-only tool that returns the size of a component for given field values, in units and in pixels (`units` × the container's density, the size `fit_marking` gives with room), with no marking created and no batch planned. It reports which axes follow the content (`follows`), whether the text was measured without library fonts (`approximate`) and, for a component that does not follow its content, a `hint`. The guide tells agents to measure with it before writing a `rect` by hand (#2083).
- `validate_library` warns about each library font (`.ttf`, `.otf` or `.woff`) that the MCP server cannot use as it is, with `file` = the specialization file and `path` = `fonts[<i>].file`: the glyph-substitution subtables it skips (`lookup type 6 format 2 ×1, …`), a font whose substitutions it turns off altogether, or a font it cannot lay out (the embedded font applies). The library stays valid, project reads stay silent and the app is not affected. A font does not need to be cut by hand any more: ship the designers' original file (#2089).

## Corrigido

- A library font with GSUB subtables the server cannot apply (chaining context formats 1 and 2, alternate substitution: Inter and Citrina have them) no longer breaks the project reads. Before, `get_project`, `plan_changes`, `propose_changes` and the renders failed with `internal-error` (`substitutionType : 62 lookupType: 6 - substFormat: 2 is not yet supported`). Now the server skips, in memory, the subtables `opentype.js` cannot apply, checks the font with a sample text when it loads, and guards every layout: a font that still fails loses its substitutions, and one that fails even then gives way to the embedded font. The supported substitutions (single, multiple, ligature, context and chaining format 3) still apply; the alternates the server skips are not drawn by it (#2089).
- `fit_marking`, the app's Arrange and the instance born without `rect` no longer leave the marking a fraction short (`component-overflow`). After measuring, the fit checks the drawing at the size it found and grows the `hug` axes by what is still missing (up to 3 times, never past the root's `maxWidth`/`maxHeight` nor the image edge), so the measure and the drawing can disagree by a fraction at any scale or density without the marking coming out short (#2086).
- The Specializations list entry now names the layers of the applied specialization (`v18 · 3 layer(s): Layout, Content, Components`), not only their count (finding F1 of the tester round, R17.3).
- `measure_component` takes `table` and `ref` values like `create_marking`: a list or table is measured with `values: { items: [{ … }] }` (before, it failed with `invalid-value`), and a `ref` field or cell takes the `mapping://` reference form (an alias fails: there is no batch).
- The fit's drawing check grows only the `hug` axis that is short (a hug × hug button short 0.3 px in width no longer gets 1 px taller) and keeps the growth that worked when another shortfall cannot be removed by growing the root.
- A library font that loses its glyph substitutions in the middle of a session (a later text made the layout throw) no longer leaves the widths measured with ligatures in the measurer's memo: the memo is dropped, so the box and the drawing agree.
- A specialization with no layers is listed as `v1 · 0 layer(s)`, without the dangling colon the layer names left (regression of the previous fix).
