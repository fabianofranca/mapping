# Settle only the affected space — 2026-11-09 (épico `epic/assentar-local`, PR #1112, MCP 0.28.6, schema v18)

## Alterado

- Settling many markings in a single container becomes much faster: 2,000 markings go from ~150 ms to ~8 ms (about 18× faster) and the time grows almost linearly with the number of markings. The result is exactly the same as before (same parents, spaces and ties).
- Creating many markings in a row and editing a large project become much faster: 1,000 markings created one by one in a container go from ~3.3 s to ~23 ms (more than 100×), and an edit (creating or moving a marking) in a project of 10,000 markings goes from ~45 ms to ~1 ms, also when the project has perspectives. The settle at the end of each operation looks only at what it touched, and the result is exactly the same as before. Measured in the model, in a cloud container, one run.
- The summary of an MCP batch no longer costs more with each marking in the project: before, each `create_marking` in the batch rebuilt the project index and reordered the short codes of all the markings just to write the label of the created marking. A batch of 1,000 creations in a project of 10,000 markings goes from ~26 s to ~0.3 s (more than 80×), and in a project of 500 markings from ~1.7 s to ~0.05 s. `plan_changes` and `propose_changes` answer exactly the same (same labels and codes); the settle of each operation still applies at its end, without deferring anything.
