# Lean tester — 2026-11-11 (épico `epic/testador-enxuto`, PR #1578, MCP 0.34.3, schema v18)

## Alterado

- The tester's `guia-base.md` now carries only the mandatory base ("Start here", section 4, the introduction of section 8, the report template and appendix A without the "Selectors and misleading names"); sections 1, 2, 3, 5, 6 and 7, the selectors and appendix B become a single line with the command and the "when to read". The base of each block of the full round drops from 85–90 thousand to 34–38 thousand characters.
- New `node scripts/testing/cloud.mjs secao <chave…>`: prints the requested section of the round guide (`1`, `2`, `3`, `5`, `6`, `7`, `A.seletores`, `B`) or of the new `docs/TESTING-NUVEM-CONSULTA.md` (`consulta.grupos`, `consulta.passada`, `consulta.regras`, `consulta.historico`), with the 25,000-character cut; without a key, it lists the keys with their size and the "when to read"; an unknown key exits with code 2 and the list.
- `docs/TESTING-NUVEM.md` drops from 43 thousand to under 32 thousand characters: the body of the "Directed round in groups", the detail of the visual pass, the rules of R21 and of the step that requires the owner, and the history of the blocks moved to `docs/TESTING-NUVEM-CONSULTA.md`, without rewriting. The prompt tells the tester to read the whole base and to request the sections through `secao` at the indicated time, and the report records the calls to `passo` and `secao`.
- The limit of 200 thousand characters per block (`tests/tooling/roundBlocks.test.ts`) now measures what the tester reads, the block's guide without the on-demand sections (now 148–151 thousand, a margin of about 49 thousand per block, instead of ~100 characters), and the base of each block has a ceiling of 45 thousand.
- `cloud.mjs run` now talks to a persistent server (`cloud.mjs serve`, detached from the terminal, on the socket `apoio/cloud.sock`): the first `run` starts it, and the following ones reuse the connection to Chrome and the `ctx`, an object that persists between calls. One `run` at a time; a timeout exits 124 and the server exits (the next `run` starts another); a dropped connection reconnects with a notice and an empty `ctx`; `run --novo` restarts; without a server, it falls back to the previous path and warns. `cloud-up.sh --restart-chrome` stops the server before closing Chrome. The body interface (`page`, `projectDir`, `state()` at the end, codes 0/1/124) stays the same.
- New `check(label, condition, detail?)` in the `run` body: it does not interrupt the body, one `✅`/`❌` line comes out per check before the `state()`, and the `run` exits 1 if any failed. "How to act" now asks for one `run` per batch of up to 8 steps, with one `check` per expected result of the screen.
- Each `run` is kept in `apoio/runs/<n>.js` (the body) and `<n>.out` (the output), with a line in `apoio/runs.log`. `cloud.mjs tempos` prints the total of `run`s and checks per test script and overall, and each ❌ in the report carries the **Reproduction** block (the `run` body, the starting folder and the `❌` line), which the fix repeats before handing it back.
- The setup script of the "Mapping - testes" environment now tries `apt-get` five times (`for i in 1 2 3 4 5; do apt-get update -q && apt-get install -y -q … && break; sleep $((i * 15)); done; true`), so the setup never fails on a 503. `cloud-up.sh` starts by checking `xdotool`, `openbox`, `import`, AT-SPI, `pyatspi` and Chrome, installs whatever is missing with the same five attempts (`CLOUD_UP_RETRY_SLEEP`, default 15 s) and exits with code **14** and the list of what is missing; Chrome is not installed (its absence is 14 right away). `cloud-up.sh <folder> --check-packages` does only that check. **Change in the environment (outside the repository):** the owner pastes the new script into the settings of the "Mapping - testes" environment.
- The retest (mode 1, findings from a previous report) is restricted: the guide comes out by the ranges of the findings' steps (`R12.10d-R12.10f`), the `passo` brings the one the range depends on, the Reproduction of each finding runs first, and the step that no finding or fix affects is not repeated. "R0 in the retest" and "Retests together" cite the ranges and the Reproduction.
- New rule in "Full round in blocks": no tester session goes past 300 thousand of final context (what `get_session` returns); a block above that is a defect, fixed by moving test scripts among the 5 blocks (table and `roundBlocks.test.ts`, respecting the chains), and the owner is called if no split into 5 fits.
