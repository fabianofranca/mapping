# Faithful components — 2026-11-08 (epic `epic/componentes-fieis`, PR #786, MCP 0.28.0, schema v18)

## Adicionado

- Component format 4, with `stroke.cap` (stroke end), `stroke.join` (corner) and `stroke.sides` (stroke only on some sides of a frame or rectangle).
- `repeat.distribute` (format 4): with `"fill"`, the list takes up the parent's space and the rows divide the height (or width) equally, minus the `gap`s.
- Expression in `layout.type`, `layout.align`, `layout.justify`, `width` and `height` (format 4), in a frame and in a slot; a value outside the set gets the default and the drawing warns `invalid value in <key>: <value>`.
- `minWidth`, `maxWidth`, `minHeight` and `maxHeight` on any node (format 4): the `fill` that hits the limit freezes and the surplus goes to the other `fill`s, as in flexbox; `min` greater than `max` is a validation error.
- `font.wrap` (`"word"` or `"none"`, a single line), `font.ellipsis` (`…` on text that does not fit) and `font.maxLines` (format 4); the MCP raster and the approximate measurement respect all three.
- Rich text (format 4): the `text` node accepts `runs` in place of `text`, a list of spans with their own weight, italic, color, decoration, family and size, which wrap together as a single text. A span with `background`, `radius` and `padding` becomes an inline box (the chip): unbreakable, it goes whole to the next line when it does not fit and follows the text. The app draws rich text; the MCP (`get_marking_image`) shows for now bars per piece and the chip background.
- Warning `text larger than the box: <node>` (the wrapped lines exceed the node's height and nothing cuts them), which enters the "The component does not fit" pending item.
- Warning `text measured with width 0: <node>` in the drawing proof of `validate_library` and in the component drawing.
- `tokens` in the specialization (`formatVersion` 15): named design values (color, number, font family), simple or per mode (`light`/`dark`), and `{ "$token": "name" }` in the component (format 4), wherever a color, number or font family is accepted, including as the result of `$switch` and `$if`. `validate_library` refuses a nonexistent token or one of the wrong type, with the node's path. The drawing mode chooses the mode (see below); with no choice, the first one applies.
- Built-in tokens `font-sans` and `font-mono` (families), which take the host theme's font and can be redefined in the specialization's `tokens`.
- Drawing mode of the project and of the container (schema v18): the **Drawing mode** control in **Settings** chooses the mode of the `tokens` (`light`, `dark`…) with which components are drawn, and the **Drawing mode** field in the container's Details sets another mode for it (or follows the project). With no mode, the first of each specialization applies. Diagnostics warns about a saved mode that no specialization declares.
- MCP: the `update_project` op of the batch changes the project's drawing mode; `add_container` and `update_container` accept `drawingMode`.
- Embeddable viewer: the `drawingMode` option (and the prop of `<MappingViewer/>`) chooses the tokens' mode; changing it at runtime (`update({ drawingMode })`) redraws without reloading the library or the screen.
- Library icon set (`formatVersion` 15 of the specialization): `icons` at the root points to a `.json` file in the package (`mapping-icons`: `viewBox` and icons by name, each with its paths, stroke, color and end) and the component's `icon` node (format 4) reads it by `name` (literal or field), with `color` and `strokeWidth`; `hug` measures the `viewBox`. A name that is not in the set draws the dashed placeholder with the warning `unknown icon: <name>`. `validate_library` checks the file, refuses a literal name outside the set and warns about the `enum` option outside it, in the app and in the MCP.
- Drawing at screen size (format 4): `screen: { anchor }` at the component's root (nine anchors) draws the template at the `size` in screen pixels, at any zoom, anchored to the marking's rectangle, and `stroke.scale: false` keeps the stroke width in screen pixels.
- Structural type (`formatVersion` 15 of the specialization): `"structural": true` on the annotation type groups without drawing; the marking does not show the name on the canvas, does not count as "without component" and `structural` together with `component` is a validation error.
- MCP: the `render_marking` and `render_container` tools return a PNG of the components' drawing (of the marking with its subtree, or of the whole container) with `zoom`, `drawingMode` and `background`. The drawing image in the MCP now has real text (embedded free font, Mapping Sans and Mono, or the library's `fonts`), with wrapping, `…` and spans, blurred shadow, dashes, stroke `align`, `cap`/`join`, `sides` and icons.
- Markings of a type with a component from 1 px, in the app, in the MCP's `create_marking`/`update_marking` and when opening the project (the component's `minSize` still applies).
- MCP: per-instance drawing proof in `plan_changes` and `propose_changes`: the component of each marking that the batch creates or changes is drawn in the rectangle and with the real values, in the container's effective mode, and the "does not fit" comes back in `issues.new` as `component-overflow` (`kind`, the node, how much is missing in px, `(approximate)` when the library does not declare `fonts`). It is a warning: it blocks neither the batch nor the proposal.
- MCP: `operationsFile` in `plan_changes` and `propose_changes`: the batch comes from a `.json` inside the roots, in place of `operations` (for measured screens with hundreds of operations). Both together, or neither, is `invalid-arguments`; outside the roots, `outside-roots`; invalid JSON, `invalid-arguments` with the position.
- Measured source (`formatVersion` 15 of the specialization): `origins[].kind` (`tree`, the default, or `measured`). The `measured` one declares only `system`, `kind`, `name` and `booleans`, and the `sources` of the types and of the system's fields say how to match each node of the measured tree (the node's `id` and classes or `type` against the type's `id` and `name`; the field's `path` in the `props`, with `values` in the `enum`s).
- MCP: the `import_measured` op of the batch (`container`, `system`, inline `tree` or `file` of a `.json` inside the roots, `offset`, `scale`) translates a tree of measured rectangles (`{ type, id?, classes?, rect, props?, children? }`) into markings with a typed annotation. The containment comes from the geometry; a node without a type and an empty rectangle are ignored with a warning (the children continue); the drawing proof warns about what does not fit (`component-overflow`).
- Agent guide: a capture example with Playwright (measures the DOM of an open page and saves the tree in a `.json`) and the example library `examples/libraries/medido/`.

## Alterado

- Schema v18: optional `drawingMode` at the root and in each container. The v17 → v18 migration only bumps the number; an earlier app opens the v18 file read-only.
- The crop of the component's root now includes the `outside`/`center` stroke and the shadow (in all versions of the format).
- The MCP raster (`get_marking_image`) now respects the stroke's end, corner and sides.
- `get_marking_image` of a container without a file uses the same drawing as `render_container` (`drawing: "rendered"`, in place of the `simplified` one with the text as bars).
- `mapping-mcp.js` grows 447,684 bytes (from 4,773,135 to 5,220,819, the minified `opentype.js` and the embedded fonts).
- The default font of text without `font.family` is now the theme's (`font-sans`, and `font-mono` for code) instead of the fixed `Inter`. Libraries whose texts do not declare `family` change text width (the `hug`, the line wrapping and the `text larger than the box` warning follow the theme's font).
- In Edit mode, the layer dots and the "+N" disappear on small markings that draw a component (smaller than 24 screen px in width or height); selected or under the mouse it shows everything and the ⚠ alert is always there. A marking without a component does not change.
- The placement of a marking without `rect` and the `near` of the MCP batch measure the text with the server's measurer (the embedded font and the library's `fonts`), in place of the approximation.

## Corrigido

- The `outside` ring (and the `inside` one) of the stroke in the MCP PNG: the raster always drew the stroke centered on the outline, ignoring `align`.
- The "the component does not fit" check gains a tolerance of 1 px per text node: a fraction-of-a-pixel excess between the DOM and the canvas no longer becomes a pending item.
- Canvas line height equal to the DOM's (checked in Chromium): `lineHeight` in px does not round and the multiple does not round before multiplying by the lines.
- The `outside` ring of the stroke at the component's root, which did not appear.
- A `fill` text in a `hug` column wrapped word by word (letter by letter, with width 0). Now the content is measured in two passes, like flexbox (in all versions of the format): the text wraps into lines of words and the frame has their height.
- The **Specializations** window shows, in the library, the drawing modes, the tokens (with the value of each mode) and the icon set file.
- The **Specializations** dialog no longer shows stray backticks around `formatVersion` (and around `repo` in the schema 11 migration notice): the interface does not interpret markdown.
- The reference field in **Details** in the narrow window (900 px) no longer cuts the target's name ("P C…"): the name of the target's layer shrinks first and, with no space, the go-to-target and clear buttons wrap to the next line.
- A library with a `kind: "measured"` source (like `medido`) now opens in the app and in the MCP: the parsed specialization left the internal keys `node` and `screen` in the source, which the parsing itself refused, and the copy saved in `specs/` and the proposal with `apply_specialization` could not be reread (`import_measured` answered "source not declared as measured").
