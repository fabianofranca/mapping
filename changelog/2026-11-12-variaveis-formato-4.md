# Variables in format 4, carousel like Compose and range slider — 2026-11-12 (epic `epic/variaveis-formato-4`, PR #1742, MCP 0.38.0, schema v19)

## Adicionado

- Variables in the component of `formatVersion` 4 (#1504, #1505): `"let": { "nome": <expression> }` in any `frame` (the root and the `template` of a `repeat` included) and `{ "$var": "nome" }` wherever an expression or condition is valid. A long subexpression that repeats is written once and used by name; reading swaps each `$var` for its content, and the drawing (app, MCP PNG, viewer and Catalog) is the same as for the component written without variables. The inner `let` hides the outer one, the order inside the same `let` is free, and `$index`, the columns of the `repeat` and `$size` inside a variable are those of the place of use.
- The variable errors state the name and the path of the use, in both languages: `variável não definida: <nome>`, `ciclo de variáveis: a → b → a`, `esperava nome de variável ([a-z][a-zA-Z0-9]*)`, `expansão das variáveis grande demais (mais de 100000 nós)` and, for the type error inside a variable, the path with `$var(<nome>)` (`template.children[1].width.$var(gap).$add[0]: precisa ser número`). `let` and `$var` in a `formatVersion` below 4 give `só é permitido com formatVersion 4`.
- `docs/component.schema.json` accepts `let` in the frame and `$var` in the expressions and conditions; the `spec-author` skill and the agent guide teach how to use them in place of repeating a long subexpression.
- MCP 0.38.0 accepts `let` and `$var` in `validate_library`, in the batch and in the drawing; `get_component` shows the file as it is. An MCP or an app earlier than 0.38.0 refuses the component with `chave desconhecida: let`: update the MCP before opening a library that uses them.

## Alterado

- The `centered-hero` carousel of `material3-compose` draws like Compose without `maxItemWidth` (#1504): at 360 wide with `itemSpacing` 8, the large item is 264 (before 232), the small ones 40 (before 56) and the first item starts at 48 (before 64); the formula holds for any width and any `itemSpacing` (large = width − 2 × (spacing + 40), inset = 40 + spacing), with fewer than 3 items a single small one of 40 aligned to the start, and the large one alone below 130 (90 with fewer than 3 items). The library's `version` goes from 10 to 11, additively (the data stay as they are; the old migrations now point to 11).
- The `carousel.json` of `material3-compose` uses variables (`let` and `$var`) in place of the repeated subexpressions: from 107 kB to 37 kB formatted, with the same drawing (the component read is the same).

## Corrigido

- The `slider` of `material3-compose` with many steps no longer loses ticks (#1504, #1506): when the space between the centers (`(width − 20) / (steps + 1)`) drops below 1 px, or `steps + 2` would exceed 1000, the `repeat` of the ticks gets 0 rows (without the `repeat limitado a 1000 linhas: marcas` notice) and each section (active and inactive; in the range, the three) draws a 4 px strip, from the first to the last tick that would be visible in it, in the color and opacity of the ticks (also disabled). Below the threshold the drawing is the one from before. In the app and in the MCP PNG.
- Catalog (CL1, #1738): the Fields table and the markdown ones fit in the dialog's width (the last column breaks a long identifier instead of being cut at the right edge); the `<dialog>` no longer scrolls (only the body, with a fixed header and footer); the Gallery reaches the left edge of examples wider than the cell (Tabs, Navigation bar); the Gallery's and Playground's frame uses the surface, and the inactive Slider track in the light theme no longer vanishes (1.04:1 → 1.27:1).
- Step R17.41 of `docs/TESTING.md` expects `C2BFC4` (the empty-image placeholder that `render_marking` already paints over `surface-container-highest` in light), in place of `E6E0E9` (#1739); the MCP PNG does not change.
