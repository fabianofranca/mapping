# Queue panel with all the plan's phases — 2026-11-12 (épico `epic/painel-fases-do-plano`, PR #1717, MCP 0.36.0 unchanged, schema v18)

## Alterado

- The "Fila de desenvolvimento" panel shows the plan's phases from the moment the stage record is written, and not only the ones that have already opened. The phases of `fases=` enter `phases` in the new state `todo` (to do), next to `open` (open) and `ok` (merged); the counter now counts the whole plan (the stage with D1 merged, D2 running and D3 not yet opened shows "1 / 3"). Every write of `painel.py` completes the rows from the record, the already written ones included, and the change counts as unpublished; the `concluída` row and the record with `fases=?` do not change, and `phase` still accepts only `ok` and `open`. The page draws the to-do phase with a dashed border and puts the state in each phase's `title`. The `implementar-fila` skill no longer tells the coordinator to write the phases as `open` when assembling the queue and gains the paragraph "Phases of the row".
- In the page's "Passo a passo" table, the issue number and the PR number become links to GitHub, opened in a new tab (`target="_blank"`, `rel="noopener"`); the cell text does not change, and an empty or non-numeric value stays as text, without a link. The already published panel gets the new page when whoever closes the next stage swaps the `files/index.html`.
