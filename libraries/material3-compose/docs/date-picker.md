# Date picker

A calendar date picker. Single picks one day; range picks an interval. In a dialog, wrap it with DatePickerDialog.

Annotation type: `date-picker` (Components layer).

## Compose

- Symbol: `androidx.compose.material3.DatePicker`
- File (`path`): `compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/DatePicker.kt`
- The `selection` field chooses the symbol; values without their own case use the base one.

| `selection`     | Symbol                                        |
| --------------- | --------------------------------------------- |
| `single` (base) | `DatePicker`                                  |
| `range`         | `DateRangePicker` (file `DateRangePicker.kt`) |

How the annotation becomes the call (the values below are examples; the parameter names and expressions are those of `params` and `values` in `code`):

```kotlin
val state = rememberDatePickerState(
    initialSelectedDateMillis = /* October 15, 2025, UTC */ 1760486400000L,
    initialDisplayedMonthMillis = /* October 1, 2025, UTC */ 1759276800000L,
)
DatePicker(state = state, showModeToggle = true)

// selection range: DateRangePicker
val rangeState = rememberDateRangePickerState(
    initialSelectedStartDateMillis = /* October 9 */ 1759968000000L,
    initialSelectedEndDateMillis = /* October 16 */ 1760572800000L,
)
DateRangePicker(state = rangeState, showModeToggle = true)

// in a dialog
DatePickerDialog(
    onDismissRequest = { /* ... */ },
    confirmButton = { TextButton(onClick = { /* ... */ }) { Text("OK") } },
) {
    DatePicker(state = state)
}
```

The displayed month comes from `month` and `year`: with both (for example, 2 and 2028), the `initialDisplayedMonthMillis` is day 1 of that month in UTC (`/* February 1, 2028, UTC */ 1832976000000L`); without one of them, it is the first day of `displayedMonth`. The drawing reads only `month` and `year` (`displayedMonth` is the month label).

Notes from `code` (what the tool hands to the agent):

> No opt-in required: `DatePicker`, `DateRangePicker`, `DatePickerDialog` and `rememberDatePickerState` with milliseconds (`Long`) are stable; only the overloads with `java.time` require @OptIn(ExperimentalMaterial3Api::class). The state comes from `val state = rememberDatePickerState(initialSelectedDateMillis = <selectedDay in the month of displayedMonth, in UTC milliseconds>, initialDisplayedMonthMillis = <first day of the month of month and year, in UTC milliseconds (without them, that of displayedMonth)>)` and the call is `DatePicker(state = state, showModeToggle = <showModeToggle>)`; `title = { Text(<title>) }` and `headline = { Text(<headline>) }` only go in when filled (without them the composable draws the defaults, and the headline comes out by itself from the chosen date). `displayedMonth`, `month`, `year` and `selectedDay` are not parameters: they are the initial state. The result comes from `state.selectedDateMillis`. In a dialog, wrap it with `DatePickerDialog(onDismissRequest = …, confirmButton = { TextButton(onClick = …) { Text("OK") } }, dismissButton = { … }) { DatePicker(state = state) }`. `today` is not a parameter: the `DatePicker` marks today by the device clock (`CalendarModel.today`, internal `todayMillis`); the field only serves the drawing.

`range` variant: No opt-in required. The state comes from `val state = rememberDateRangePickerState(initialSelectedStartDateMillis = <rangeStartDay in UTC milliseconds>, initialSelectedEndDateMillis = <rangeEndDay in UTC milliseconds>, initialDisplayedMonthMillis = <first day of the month of month and year, in UTC milliseconds (without them, that of displayedMonth)>)` and the call is `DateRangePicker(state = state, showModeToggle = <showModeToggle>)`, with `title` and `headline` as in the base. The result comes from `state.selectedStartDateMillis` and `state.selectedEndDateMillis`. In a dialog, wrap it with `DatePickerDialog` (file `DatePickerDialog.kt`), like the `DatePicker`.

## Examples

- **One day**: headline=Wed, Oct 15, displayedMonth=October 2025, selection=single, selectedDay=15
- **Range**: headline=Oct 9 – Oct 16, displayedMonth=October 2025, selection=range, rangeStartDay=9, rangeEndDay=16
- **No selection**: displayedMonth=October 2025, selection=single, showModeToggle=false
- **Range until the end of the month**: headline=Oct 27 – Oct 31, displayedMonth=October 2025, selection=range, rangeStartDay=27, rangeEndDay=31
- **February 2028 (leap year)**: headline=Tue, Feb 29, displayedMonth=February 2028, month=2, year=2028, selection=single, selectedDay=29
- **30-day month, 6 rows**: headline=Sun, Nov 30, displayedMonth=November 2025, month=11, year=2025, selection=single, selectedDay=30
- **28-day month, 4 rows**: headline=Sat, Feb 14, displayedMonth=February 2026, month=2, year=2026, selection=single, selectedDay=14
- **Range that crosses weeks**: headline=Feb 3 – Feb 12, displayedMonth=February 2028, month=2, year=2028, selection=range, rangeStartDay=3, rangeEndDay=12
- **Hovered**: headline=Wed, Oct 15, displayedMonth=October 2025, selection=single, selectedDay=15, interaction=hovered
- **Focused**: headline=Oct 9 – Oct 16, displayedMonth=October 2025, selection=range, rangeStartDay=9, rangeEndDay=16, interaction=focused
- **Pressed**: displayedMonth=October 2025, selection=single, interaction=pressed
- **Today's day**: headline=Wed, Oct 15, displayedMonth=October 2025, selection=single, selectedDay=15, today=22

**How the drawing follows Compose**

- A 360 container in `surface-container-high` (`ContainerColor`) with `corner-extra-large` (28) corners, no shadow: the `DatePickerDialog` only applies `tonalElevation` (`Level0`), and the token's `ContainerElevation` does not become a shadow. The root carries `minWidth: 360` (the `sizeIn(minWidth = ContainerWidth)`), and the height is that of the content (`hug`).
- A 120 header (`HeaderContainerHeight`, the frame's `minHeight`), with the 1 divider in `outline-variant` inside it, at the base. The title sits at the top, 24 from the left and 16 from the top, in `label-large` and `on-surface-variant` (`HeaderSupportingTextColor`). The headline is `headline-large` (32, line 40) in `on-surface-variant`, with `maxLines: 1` (the `DatePickerHeadline`'s `Text`), 24 from the left and 12 from the bottom, centered in the 60 row that the mode button (48 plus the 12 bottom of the `DatePickerModeTogglePadding`) defines. The mode button is the set's `edit` icon, 24, in a 48 area flush 12 from the right. Without the button (`showModeToggle` false) the row shrinks to the headline's 52.
- Single: the month row is 56 (`MonthYearHeight`) with 12 on each side. On the left the year button (`TextButton`, 40 high, sides of 12): the month in `label-large` and `on-surface-variant`, 8 of space and the 24 `arrow_drop_down` icon. On the right the two 48 arrows (`keyboard_arrow_left` and `keyboard_arrow_right` of the set, 24, in `on-surface-variant`). Without `displayedMonth` the button shows `-`, like Compose's `?: "-"`.
- Weekdays: seven 48 cells starting 12 from the edge (`SpaceEvenly` in 336), in `body-large` and `on-surface` (`WeekdaysLabelTextColor`), with the English initial starting on Sunday.
- Grid: 48 cells (`RecommendedSizeForAccessibility`) starting at 12, the number in `body-large` and `on-surface`, in a 40 circle. With `month` and `year` the grid is that of the month, without a table: the number of days (28, 29, 30 or 31, with the leap year rule) and the weekday of day 1 come from arithmetic over the two fields (the days counted since March 1, in `$floor`, `$mod` and `$add`, the same computation as any Gregorian calendar), and the cells are a `repeat` by `count` (one per day, with `$index`) whose position is the column `(position) mod 7` and the row `position ÷ 7`. The grid height is that of the content (`hug`): 4, 5 or 6 rows of 48, depending on where the last day falls. Without `month` or without `year`, today's grid stays: 31 days starting on Wednesday, five rows. The selected day (`selectedDay`) is a 40 circle (`DateContainerWidth` and `Height`, `corner-full`) in `primary`, with the number in `on-primary` (`DateSelectedContainerColor` and `DateSelectedLabelTextColor`), inside the day's own cell (the cell computes whether it is the selected day, an end of the range or part of the band by the `$index`).
- Range (`DateRangePicker`): the header is inset 64 (`DateRangePickerTitlePadding`), the headline is `title-large` (22, line 28) and the minimum height is 68 (`RangeSelectionHeaderContainerHeight` 128 minus the `HeaderHeightOffset` 60); without the arrows row, the month appears as a subtitle after the weekdays, in `title-small` and `on-surface-variant`, with inset 24, 20 on top and 8 at the bottom. The ends (`rangeStartDay` and `rangeEndDay`) are 40 circles in `primary` with the number in `on-primary`; the band is 40 in `secondary-container` (`RangeSelectionActiveIndicatorContainerColor`), with no corner, from the center of the start cell to the center of the end cell, crossing the whole width in the middle weeks, like `drawRangeBackground`: each cell of the range paints its part (the start one only the right half, the end one only the left half, the middle ones whole), and the parts join into a single band per week.
- Interaction state (`interaction` field): `none`, `hovered`, `focused` and `pressed`. `DatePickerModalTokens.kt` (lines 9 to 68) names no day states (only `DateStateLayerHeight` and `Width` 40 in the `CornerFull` shape, lines 24 to 26), and the `Day` of `DatePicker.kt` (1993 to 2050) is a clickable `Surface` that paints the layer through the Material ripple (`StateTokens.kt`): `hovered`, `focused` and `pressed` are the ripple states. The state applies to the **chosen item**: the selected day (in the range, the start day; with no selection, day 1). The layer is the `state` node, a still 40 circle, over the day, in the day's content color (`on-primary` on the selected day, `on-surface` on day 1 with no selection) with the opacity of `state-hover` (0.08), `state-focus` (0.10) or `state-pressed` (0.10). The type has no `enabled` (the disabled day comes from `SelectableDates`, which is not a field), so there is no disabled state that wins: the state always draws.
- The icons come from the library's set (`icon` node), and the fonts and colors, from the tokens. The file dropped from 120 kB to under 80 kB and, with the computed grid (EX4 of stage #897), to 44 kB: there is no SVG path, literal color, day table or `$switch` of dozens of cases anymore.
- The month of the year button, the weekdays, the day numbers and the numbers of the selected day and of the range ends are centered by the capital letter height (`font.verticalAlign: "cap-middle"`); the title, the headline and the month subtitle stay as they are. Compose's `Text` centers by the font's line box; with Roboto the two coincide within 1 px.

**What still differs from Compose**

- The grid reserves 6 rows in Compose (`RecommendedSizeForAccessibility` 48 × `MaxCalendarRows` 6, `DatePicker.kt` lines 2293 and 2303), which gives a height of 512, and the `size` is 360 × 512. The drawing has the month's rows (4, 5 or 6, `hug`): the content measures 416, 464 or 512 (single) and 369, 417 or 465 (range), and the dialog height follows the month. The `size` of 512 is that of the five-row month, and the background fills the box: with 4 rows, the content is smaller than the box (96 are left at the bottom in single), and with 6 rows it fits in the 512 (accepted effect, as in #863).
- Today comes from the `today` field (day of the month, 1 to 31), because the drawing has no clock: the 1 outline in `primary` (`DateTodayContainerOutlineWidth` and `DateTodayContainerOutlineColor`, `DatePickerModalTokens.kt` lines 38 and 39; the `Day`'s `Surface`, `DatePicker.kt` lines 2024 to 2029) and the number in `primary` (`DateTodayLabelTextColor`, line 40; `dayContentColor`, lines 936 to 950). The selected day wins over today (`today && !selected`, line 2024): no outline, with the filled circle and the number in `on-primary`. Inside the range band, without being an end, the outline appears and the number follows the band color (`inRange` comes before `isToday` in `dayContentColor`). With `month` and `year`, a `today` that the month does not have draws nothing; without the field, no day gets the outline. Compose uses the device clock (`CalendarModel.today`, `DatePicker.kt` line 1713), and the code does not carry the field.
- The days inside the range, between the ends, keep the number in `on-surface`; Compose uses `on-secondary-container` (`SelectionDateInRangeLabelTextColor`). Format 4 already compares numbers, but the number color inside the band was not migrated (the scene of the earlier examples had to stay identical, and the color difference is small: `on-surface` and `on-secondary-container` almost blend in light and in dark). The band, which depends only on the position of the ends, is exact.
- A day that the month does not have (30 in February, 45) draws neither circle nor band, and a `rangeEndDay` beyond the month takes the band to the last day of the month (Compose does not allow choosing that day). `month` outside 1 to 12 is not checked: the computation rolls over to the next month (13 is January of the next year).
- No disabled state of the days (`SelectableDates`) and of the month (`previousAvailable` and `nextAvailable` of the arrows), no open year picker, no typing mode (`DateInput`), no shadows or animations (the month swap, the day's `animateChecked`). The interaction state is only that of the chosen item (`interaction` field), a still layer: the other days have no state and there is no animated ripple or focus ring.
- No dialog buttons (`DatePickerDialog`: OK and Cancel, the token's `ContainerHeight` 568) nor the close and save of the `DateRangePicker`'s full screen, which the `HeaderHeightOffset` already discounts.
- The `DateRangePicker` shows a scrollable vertical list of months, and the drawing shows only the month of `displayedMonth`. The range headline in Compose is a row of two texts (`startDatePlaceholder`, the `-` delimiter and `endDatePlaceholder`); here it is a single text, the `headline`.
- Compose's `sp` sizes are drawn in px (1 sp = 1 component px). The title wraps like Compose's `Text` and makes the header grow; the headline stays on one line (`maxLines`), cut without an ellipsis (the default `overflow` is `Clip`).
