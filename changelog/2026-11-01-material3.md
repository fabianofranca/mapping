# Material 3 library — 2026-11-01 (epic `epic/material3`, PR #260, MCP 0.12.0, schema v13)

## Adicionado

- Specialization `formatVersion` 9 with `variants` in a platform's `code`: an `enum` field of the type picks the code variant, which swaps the `symbol` (in Compose, `Button`, `OutlinedButton`, `TextButton`), the `path` and the `notes` and adds `params` and `values` to those of the base. One level only; versions 1 to 8 are still accepted unchanged, and `variants` in an earlier version is the error `only allowed with formatVersion 9`, at the exact path.
- Variants table in the Catalog: below the platform's code, "Variants (field)" lists each value and its symbol.
- Test script R16 (Variants in the code), done by the agent alone.
- The **Material 3 (Compose)** library brings the Roboto font (400 and 500, `.woff2` from Fontsource, OFL license in `fonts/LICENSE-Roboto.txt`) and validates with no warnings.
- `examples/material3-compose.zip`: the `libraries/material3-compose/` package zipped (the contents at the root), to apply in Specializations › **Apply zip…**; generated by `npm run build:material3-zip` and checked by a test.
- Test script R17 (Material 3 (Compose) library), done by the agent alone: checks the zip and the package, applies the zip in the app, maps a screen (Scaffold, Top app bar, LazyColumn with List items, outlined Button and FAB) through a proposal and checks that `get_code_hints` returns the tree with the right composables (`Scaffold`, `TopAppBar`, `LazyColumn`, `ListItem`, `OutlinedButton`, `FloatingActionButton`).
- **Material 3 (Compose)** library ready to use in `libraries/material3-compose/` (specialization `formatVersion` 9, not built in: apply it from the folder or from a zip of it): 50 types in three layers (Layout: Scaffold, Surface, Box, Row, Column, LazyColumn, LazyRow, LazyVerticalGrid, FlowRow, Spacer, HorizontalPager; Content: Text, Icon, Image; Components: Top app bar, Button, FAB, Extended FAB, Text field, Switch, Checkbox, Chip, Card, List item, Navigation bar, Bottom sheet, Icon button, Icon toggle button, Segmented button, Radio button, Slider, Search bar, Date picker, Time picker, Badge, Snackbar, Tooltip, Progress indicator, Secure text field, Divider, Alert dialog, Dropdown menu, Navigation rail, Short navigation bar, Navigation drawer, Tabs, Bottom app bar, Carousel, Pull to refresh, Swipe to dismiss), each with the `compose.material3` 1.4.0 composable in the `code` (the file in androidx, the parameters and the variants that swap the composable), component, document and examples.

## Alterado

- MCP: `get_annotation` and `get_marking` return the `code` already resolved to each annotation's variant (no `variants` in the output); `get_code_hints` keeps the base's raw `code` in `types` and brings the variant's resolved `code` in the annotations of the `tree` for types with `variants`; `get_specialization` and `get_component` keep returning the raw JSON.
- MCP: `find_by_code` compares against each annotation's resolved code (searching for the base's symbol only returns the base's annotations, a variant's only its own; searching by `path` returns all). Nothing changes in specializations 1 to 8.
- The "Definition" in Details shows the file and symbol of the annotation's variant.
- `validate_specialization`, `validate_library` and `apply_specialization` accept `formatVersion` 9, with the same errors as the app.

## Corrigido

- Library validation no longer warns "field not used by the drawing" when the type's `code` uses the field (`params`, `values`, `variants` or the `notes`): Material 3 (Compose) went from 82 to 50 warnings. The minimum size (`minSize`) of the library's components stayed only where the androidx code defines a minimum on both axes (corrected values: Button 58 × 40, text fields 280 × 56, Search bar 360 × 56); in the others the field was removed, and the validation's drawing proof now draws only the initial size (the minimum size is no longer drawn): Material 3 (Compose) now brings the Roboto font (`.woff2` from Fontsource, OFL license) and validates with no warnings, and the example library `examples/libraries/material3/` went from 42 to 3.
- The exported zip now carries, unchanged, the copy in `specs/` of a specialization that the app cannot read (greater format version, invalid file or different `id`); before, it was left out and the zip cited a missing copy.
