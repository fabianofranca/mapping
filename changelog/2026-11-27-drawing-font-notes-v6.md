# One drawing font, a token named by a field value and notes library v6 — 2026-11-27 (épico `epic/drawing-font-notes-v6`, PR #2898, MCP 0.61.0, schema v24 unchanged)

## Adicionado

- The drawing font: component text in the built-in `font-sans` and `font-mono` is now drawn with the embedded **Mapping Sans** and **Mapping Mono**, the same files the MCP measures and draws with, in the app canvas, the Catalog, the library preview and the viewer. The drawing no longer depends on the operating system's font, and a box the MCP fits (`fit_marking`, `create_marking` without `rect`, `measure_component`) is no longer cut in the app. Every project switches, with no opt-in and no schema change. The interface keeps the system font, and a library that redefines `font-sans` or `font-mono` in `tokens.values` still wins.
- `mapping-viewer` 0.12.0: the viewer registers the four Mapping faces on its first `createViewer` (the `./formats` entry before it sizes the boxes) and redraws when they load; its `fonts` option default is the model's. The host passes nothing. The bundles grow by about 100 KB each.
- `measure_component` and the drawing proof of `plan_changes` and `propose_changes`: a text in the default font (a family stack that starts with `Mapping Sans` or `Mapping Mono`) is exact, so `approximate` is `false` and `component-overflow` items drop the `approximate` flag and the `(approximate)` suffix for it. A stack that starts with another name that is not a library font (`sans-serif`, `Inter`) stays approximate. The library validator does not change.
- `$tokenNamed` in component format 4 (no version change): `{ "$tokenNamed": <text expression>, "default"?: … }` in a color or font-family position reads a token **named by a field value**. The name is looked up among the tokens each applied specialization declares: the component's own library first, then the other libraries in `specializations[]` order, then `font-sans` and `font-mono`, each in the drawing selection of the marking's space (a container pinned to `dark` reads the `dark` value). The first token of the position's kind wins; with none, a text that is itself a color or a family stack is used as is, else `default`, else the attribute's default. The app and the MCP (`measure_component`, `fit_marking`, `create_marking` without `rect`, the drawing proof, the renders) resolve it the same way; the Catalog, the library preview, `validate_library` and the viewer read the component's own library and the built-ins. Outside a color or font-family position it is the error `$tokenNamed is only valid where a color or font family is expected`; below format 4, `only allowed with formatVersion 4`. The name is data: nothing checks it, and a name that resolves to nothing draws the default.
- Notes library version 6, the note: `nota` gains a `cor` field with six colors (`yellow`, `blue`, `green`, `pink`, `orange`, `gray`; empty is `yellow`; the fill and the text go together) and now holds the table, with a `texto` (optional now) and a `textoDepois` around the `linhas` rows (`chave` and `valor`). A part with no value takes no room, so a note with only rows is a table. The package has five files (the specialization, the `nota` and `texto` components and their two documents).
- `texto` of the notes library: `familia` (the name of a font token of an applied library, such as `font-mono`, or a family stack; empty is `font-sans`), `alinhamento` (`start`, `center`, `end`) and `cor` by color token name or `#RRGGBB` (a name that resolves to nothing draws `#1F1F1F`), all read through `$tokenNamed`. New projects (app and MCP `create_project`) are born with version 6.
- `docs/TESTING.md`, script R49 (Notes v6 and the drawing font, 17 steps with its own visual pass), in block 4 of the full round: the six note colors, the table in the note, the `texto` family, alignment and color, the `$tokenNamed` fallbacks and the update of a version 5 project with a `tabela`.

## Alterado

- `DEFAULT_SANS` and `DEFAULT_MONO` of the model are `"Mapping Sans", sans-serif` and `"Mapping Mono", monospace`. The app no longer passes the theme's font stack to the component libraries (`readHostFonts` and `hostFontsFrom` are gone).
- A family stack that is just `Mapping Mono` (no generic after it) now measures with the mono face in the server.
- `docs/TESTING.md`, R12.47, R12.48, R25.26 and R39.16: the widths, the clipped box and the `approximate` values are recomputed for Mapping Sans and Mono.
- The `dist/index.html` ceiling went up 80 KiB, from 2654208 to 2736128, by the budget rule; above the limits, `bug` #2895 for the owner to review
- The `dist/index.html` ceiling went up another 16 KiB, from 2736128 to 2752512, by the budget rule; above the limits, `bug` #2908 for the owner to review
- The `tabela` type of the notes library is removed. Version 6 migrates it into `nota` (`rename-type`, versions 1 to 5), so a table becomes a yellow note with the same title and rows. Existing projects only move with **Update to the built-in version** in the app, or `builtin` `notas` in `plan_library_update` and `update_specialization`; nothing changes on its own.
- `docs/TESTING.md`: the scripts that named the notes library at version 4 or 5 (R0.2, R1.20d, R9.3, R10.8, R12.13, R12.15, R12.27, R12.45, R12.54 to R12.56 and the setups of R12) now expect version 6. The full round goes from R0 to R48 to R0 to R49.
