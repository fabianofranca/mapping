# CR of the model — 2026-11-09 (épico `epic/cr-model`, PR #1191, MCP 0.28.12, schema v18)

## Alterado

- A specialization with an unknown key in `tokens` (besides `modes` and `values`) is now refused, with the error `unknown key: <key>` at its path; before, the extra key passed silently. The `formatVersion` stays at 15.
- A type with `requiresOwner` whose only possible owner is itself (in `formatVersion` 13, which accepts children of the layer itself) is now refused, with the error `no other type accepts it as a child`, at the path `…requiresOwner`: no annotation could be the owner. A library that passed like this before may be refused now.
- A library that cites a component, font, icons or `componentPaths` with `..` leaving the package folder now gets the problem `path outside the library: <ref>`, at the path of whoever cites it; before, the `..` was silently dropped
- An `origins` root with `margin` and without `anchor` is now refused (`margin only applies with anchor`, at the root's `margin` path); before, it passed

## Corrigido

- An instance's label never shows `[object Object]`: a table value counts as empty and falls back to the type's name
- Two specializations with the same `system` in the measures import (`measured`) each use their own `booleans`
- The translation of an external JSON without `system` uses the first `tree` origin; with only `measured` origins, the error tells you to pass the `system`
- The `padding` of a `runs` segment accepts a numeric `$token`, as the doc already said
- A `slot` inside a nested `repeat` is no longer reported twice
- Updating a library with a `map-values` step that maps a value to itself, or a `rename-field` with the same name on both sides, no longer counts values and annotations as changed in the migration report.
- The `path-without-repo` notice (a platform with `path` and without `repo`) now also counts the `path` of the `variants.cases` cases.

- A citation label with `*`, `_` or a backtick (`a*b*c`) comes back the same when reread from the conversation text: before, the markers were read as emphasis and vanished.
- Citing a deleted proposal (`p/botoes`) no longer points to another proposal with a similar id (`botoes-2`): a proposal citation only resolves by the exact id.
- Pasting `**mapping://…**` (or with `_`, a backtick or `~~` around it) into the conversation composer becomes the chip normally, without carrying the markers into the address.
- A markdown list whose first item is indented and followed by items without indentation (`  - a` and `- b`) stays a single list, instead of two.
- Two copies of a conversation with the same messages now follow the copy with the higher `revision`: an interrupted reopening (opened at `revision` 6, resolved at 5) stays open, instead of going back to resolved.
- The conversation subject shows a citation's live label as it is (`__init__` does not become `init`).
- Resending the same `container` and the same `rect` of a locked marking (`update_marking`, full re-export) no longer gives `locked`: repeating the current space is not a change, as it already was with the `rect` alone.
- A container id can no longer be reused by a marking, an arrow or the item wrapper (nor that of a marking or arrow by a container): before, both passed and the project ended up with two items with the same id.
- The deletion dialog for a selection now also counts the locked markings that are selected and go out along with the selected parent or container: it says everything it deletes.
- A code file link whose `urlTemplate` has `{line}` in both the query and the fragment no longer leaves a literal `{line}` over: both are replaced.
- Remote images from `.home.arpa`, `.lan` and `.intranet` hosts are now treated as a local network (refused with the switch off), like `.local` and `.internal`.
- A `mapping.json` newer than v10 or v12, edited by hand with `urlTemplate` in `platformRepos` or `inherit` in an annotation, no longer gets the notice of data discarded in the migration.
- An annotation removed in a proposal from before v14 (without `parentRole` in the earlier value) no longer shows up as a false conflict in the review: a missing `parentRole` counts as `null`, on both sides.
- A typed annotation with a missing field named `toString` (or another name inherited from `Object.prototype`) no longer brings down `computeChanges` and the MCP's `propose_changes`.
- A component with `$switch` on a field whose value is `toString`, `constructor` or another name inherited from `Object.prototype` falls to the `default`, instead of returning a function.
- The `layout` `padding` coming from `$field` accepts numeric text (`"16"`): non-numeric text counts as 0 and the value is never below 0, like `gap`.
- The ellipsis (`ellipsis`) of a text cut in the middle of an emoji no longer produces a broken character: the cut is by code point.
- A screen with an anchored `fill` root never ends up with a negative width or height.
- In a screen `layout`, `fill` children on the main axis with `minSize` redistribute the surplus (the final size respects the `minSize` and the sum fits in the parent), as in the instantiation of a component.
- Moving a screen instance one position down (`moveSibling` with a positive `delta`) places it after the next sibling, instead of skipping another.
- The messages of the catalog (a component that did not load, a type outside the specialization), of Arrange, of broken, cyclic or multi-level references and of the library's component and icon problems appear in the app's language; with the app in English (US) they no longer come out in Portuguese. The MCP output does not change.
- A component's drawing recognizes "does not fit" by an engine field, no longer by the start of the notice text.
- The chip of a proposal that the MCP links to the conversation (`mapping://<projeto>/p/<8 hex>`) resolves again in the app instead of showing "The cited item no longer exists"; the free prefix is still refused (a deleted `p/botoes` does not fall to `botoes-2`).
- The **Last message** column of the **Comments** window no longer shows backslashes (`a\b\c`) in the label of a citation with escaped `*`, `_` or backtick: it shows `a*b*c`.
